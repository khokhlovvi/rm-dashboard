# Дашборд активности клиентских менеджеров

Веб-дашборд для руководителя: звонки и встречи клиентских менеджеров (РМ), недельный план
«3 стратегические встречи + 6 фоллоуапов», рейтинг, сравнение менеджеров, сигналы «Внимание».
Работает сразу на демо-данных (16 вымышленных менеджеров × 40 недель) и принимает импорт CSV/XLSX.
Всё считается в браузере, внешних серверов нет.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # Vitest: периоды, классификация, метрики, импорт
npm run build      # проверка типов + сборка в dist/ (статические файлы, можно открыть с любого веб-сервера)
npm run lint       # ESLint
npm run demo       # выгрузить демо в data/sample/demo.csv (по схеме импорта)
```

Нужен Node.js 22.18+ (скрипт `npm run demo` запускает TypeScript напрямую).

## Экраны

| Экран | Что показывает |
|---|---|
| **Обзор** | KPI: звонки, встречи, конверсия звонок → встреча, активные менеджеры — с ▲▼ к предыдущему такому же периоду; звонки и встречи по неделям (два отдельных графика); статус плана 3 + 6 за прошлую неделю; сводка недели текстом; план/факт с прогнозом к концу месяца; воронка |
| **Рейтинг** | Таблица с сортировкой по любому столбцу: место, звонки и встречи с динамикой, конверсия, стратегические, фоллоуапы, план %, отклонение от среднего и от лучшего, смена места, спарклайн за 12 недель. Метрика рейтинга выбирается. Экспорт CSV/Excel |
| **План 3 + 6** | Менеджер × 10 последних недель («N/3 · N/6», цвет и значок статуса), кто выполнил полностью / частично / не начал на прошлой неделе, недель выполнено за месяц и с начала года. Экспорт |
| **Сравнение** | Бок о бок 2–4 менеджера; тепловая карта «менеджер × неделя» (звонки/встречи, 8–40 недель); «менеджер × продукт» (11 продуктов); глубина портфеля; доля продуктов и редкие продукты; воронки по менеджерам |
| **Карточка менеджера** | KPI с местом в команде, звонки и встречи по неделям против среднего команды, конверсия по неделям, таблица сравнения с командой, история плана за 16 недель, продукты, воронка, план/факт |
| **Внимание** | Падение активности на 30%+ к предыдущему периоду, падение встреч, активность ниже порога, нет встреч 7+ дней или 0 встреч за период, план прошлой недели не начат |
| **Импорт** | Загрузка CSV/XLSX, автосопоставление колонок, ручная правка, предпросмотр, предупреждение о колонках с данными клиентов |
| **Настройки** | Нормативы плана, порог 180 дней, режим определения стратегической встречи, пороги сигналов, опорная дата |

Фильтры в шапке: период (прошлая неделя / неделя / месяц / с начала года / произвольный по
календарю), подразделение, менеджер, продукт. Тема — авто/светлая/тёмная. «Печать» — версия для
планёрки (без шапки и кнопок, всегда светлая, с подписью периода).

## Формат данных

Одна строка = одна активность. Первая строка — заголовки. CSV с разделителем `;`, `,` или таб
(кодировка UTF-8, BOM допустим) или XLSX (первый лист).

| Поле | Обяз. | Значения | Примеры заголовков, которые узнаются |
|---|---|---|---|
| Дата | да | `ДД.ММ.ГГГГ`, `ГГГГ-ММ-ДД`, дата Excel; время отбрасывается | дата, дата контакта, date |
| Менеджер | да | ФИО или код | менеджер, РМ, ответственный, сотрудник |
| Подразделение | нет | любой текст | подразделение, отдел, офис, филиал |
| Тип активности | да | звонок / встреча (также call, meeting, визит) | тип, тип активности, канал |
| Результат | нет | договорились о встрече / открыт продукт / отказ; иное — «без результата» | результат, итог |
| Продукт | нет | один или несколько через `,` `;` `/` `\|`; синонимы приводятся к справочнику («зарплатный проект» → ЗП-проект) | продукт, продукты |
| Вид активности | нет | стратегическая встреча / фоллоуап / прочее | вид активности, цель, категория |
| Дней с последней встречи | нет | число дней с прошлой встречи с этим клиентом | дней с последней встречи |
| Дата последней встречи | нет | если нет числа дней — дашборд посчитает сам | дата последней встречи, последняя встреча |
| Новый клиент | нет | да/нет, 1/0 | новый клиент |

Пример: [`data/sample/sample-import.csv`](data/sample/sample-import.csv) (2 недели демо), шаблон
можно скачать на экране «Импорт».

Сопоставление колонок: дашборд угадывает поля по заголовкам, всё можно поправить вручную; выбранное
сопоставление запоминается для файлов с теми же заголовками. **Берутся только сопоставленные
колонки** — остальные (клиент, телефон, ИНН, счёт…) отбрасываются до сохранения, а колонки, похожие
на данные клиентов, показываются в предупреждении. Импорт хранится в `localStorage` этого браузера;
кнопка «Вернуться к демо-данным» удаляет его. Реальные выгрузки держите в `data/private/` — папка в
`.gitignore`.

## Как считается

Подробно — в [`docs/PLAN.md`](docs/PLAN.md). Коротко:

- **Неделя** — ISO, пн–вс; номер и год недели — по четвергу (29.12.2025 — это 2026-W01).
- **Периоды**: прошлая неделя (пн–вс перед текущей), неделя / месяц / год — накопительно до опорной
  даты. Сравнение — с предыдущим таким же периодом: неделя — с тем же днём прошлой недели, месяц — с
  теми же днями прошлого месяца (31.03 → 28.02), год — с той же датой прошлого года.
- **Опорная дата** — сегодня, если данные не старше недели; иначе последняя дата в данных; можно
  задать вручную в настройках.
- **Конверсия звонок → встреча** = звонки с результатом «договорились о встрече» / все звонки.
- **Стратегическая встреча** — встреча с новым клиентом или с клиентом, с которым не было встреч
  180+ дней (порог — в настройках). Режим «авто»: если в строке есть число дней или дата последней
  встречи — считаем сами по порогу; если нет — берём признак «стратегическая встреча» из системы
  мониторинга.
- **Фоллоуап** — звонок или встреча с видом «фоллоуап». **Стратегическая встреча в фоллоуапы не
  засчитывается** (одна встреча закрывает только одну часть плана); правило переключается в
  настройках.
- **План недели**: выполнение = (min(стратег., 3)/3 + min(фоллоуап, 6)/6) / 2.
  «Выполнен» — обе части ≥ норматива; «не начат» — 0 и 0; иначе «частично».
  За месяц/год — число завершённых недель со статусом «выполнен»; неделя относится к месяцу и году
  своего четверга; недели до начала данных не учитываются.
- **Рейтинг**: место по выбранной метрике (равные значения делят место), отклонение от среднего по
  команде и от лучшего, динамика к предыдущему периоду.
- **Прогноз месяца** = факт / прошедшие рабочие дни × рабочих дней в месяце (пн–пт, без праздников).

## Как добавить метрику

1. Если метрике нужен новый счётчик по активностям — добавьте поле в `AGG_FIELDS` и заполнение в
   конструкторе `Cube` (`src/core/metrics.ts`). Суммы по любому периоду появятся автоматически.
2. Добавьте ключ в `MetricKey`, подпись в `METRIC_LABELS` и формулу в `metricValue`
   (`src/core/ranking.ts`). Метрика сразу станет доступна в выборе метрики рейтинга, «Бок о бок» и
   (если добавить в `CARD_METRICS`) в карточке менеджера.
3. Столбец в таблице рейтинга — `src/ui/screens/ranking.ts` (заголовок `th(...)`, ячейка и `val`
   для сортировки), в экспорт — `exportRows`.
4. Тест на формулу — в `tests/metrics.test.ts`.

## Решения

Принятые без уточнений, по умолчанию; всё меняется в настройках или коде.

- **Без UI-фреймворка и без библиотеки графиков.** Нужны линии, спарклайны и тепловые карты — это
  ~200 строк SVG (`src/ui/charts.ts`) с полным контролем над темами и подсказками; бандл ~29 КБ gzip.
  XLSX читается/пишется лёгкими `read-excel-file` / `write-excel-file` (подгружаются только при
  импорте/экспорте). SheetJS из npm не взят: версия там устаревшая, с известными уязвимостями.
- **Хранилище — `localStorage` браузера**, а не SQLite: без сервера это самый простой локальный
  вариант; импорт упаковывается компактно (справочник менеджеров + массивы). Если файл не влезает
  (~5 МБ), данные работают до перезагрузки, об этом есть предупреждение.
- **Демо генерируется в браузере детерминированно** (seed), заканчивается сегодняшним днём, поэтому
  дашборд всегда «свежий». Профили менеджеров дают рост, спад, отпуск, новичка и сезонность; на
  прошлой неделе гарантированно есть полное, частичное и нулевое выполнение плана.
- **Активность** = звонки + встречи (метрика рейтинга по умолчанию; взвешивание не вводил).
- **Сигналы «Внимание»** считаются для выбранного периода против предыдущего такого же; падение
  ниже 30% не поднимается при базе меньше 5 активностей (иначе шум у новичков). Дополнительно
  отслеживается падение именно встреч (база ≥ 3), т.к. звонки могут маскировать отсутствие встреч.
- **«Не делал встреч неделю»** = последняя встреча 7+ дней назад к опорной дате или 0 встреч за
  выбранный период длиной от недели.
- **План/факт по звонкам и встречам**: норматив 15 звонков и 5 встреч на менеджера в неделю (в ТЗ
  чисел не было); месячный план = недельный × рабочие дни / 5; праздники не учитываются.
- **Сводка недели** — шаблон по правилам (рост/падение ≥ 15%, лучшая конверсия при ≥ 10 звонках,
  редкие продукты < 3% упоминаний). Внешний API не подключал: по ТЗ без ключа — шаблон, а сервера,
  где можно было бы безопасно хранить ключ, нет.
- **«Глубина портфеля»** = число разных продуктов, упомянутых менеджером за период. **Редкие
  продукты** — меньше 4% всех упоминаний команды (на демо — депозит и факторинг).
- **Цвет не единственный носитель смысла**: везде стрелки ▲▼→, подписи статусов (✓ выполнен,
  ≈ частично, ✕ не начат), числа в клетках тепловых карт.
- **Цвета** — проверенная на дальтонизм палитра: звонки синие, встречи оранжевые, среднее команды —
  серый пунктир; тёмная тема — отдельно подобранные оттенки.

## Ограничения и что дальше

- Праздничные дни в прогнозе не учитываются (только пн–пт).
- Старый формат `.xls` не читается — нужно сохранить как `.xlsx` или CSV.
- Сравнение «с начала года» с прошлым годом на демо пустое: демо — 40 недель текущего года.
- Нет авторизации и общего хранилища: каждый браузер видит свои импортированные данные.

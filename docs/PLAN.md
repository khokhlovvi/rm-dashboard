# План: дашборд активности РМ

## 1. Модель данных

Одна строка = одна активность менеджера. Только агрегируемые поля, без данных клиента.

```ts
interface Activity {
  date: string;                 // 'YYYY-MM-DD'
  manager: string;              // ФИО/код менеджера
  department: string;           // подразделение ('' если нет)
  type: 'call' | 'meeting';
  result: 'meeting_set' | 'product_opened' | 'refusal' | 'none';
  products: string[];           // упомянутые продукты (0..n)
  kind: 'strategic' | 'followup' | 'other'; // вид активности из источника
  daysSinceLastMeeting: number | null;     // из системы мониторинга
  newClient: boolean;           // новый клиент (если источник даёт флаг)
}
```

После загрузки каждая активность классифицируется (`src/core/classify.ts`) с учётом настроек:
`strategic: boolean`, `followup: boolean`. Затем строится «куб» — суммы по менеджеру × дню
(`src/core/metrics.ts`), из которого любой период считается суммированием дней.

Справочник продуктов (11): БГ, РКО, ЗП-проект, ВЭД, Программа лояльности, ЦР, Эквайринг, FX,
Кредит, Депозит, Факторинг. Незнакомые продукты из импорта сохраняются как есть.

Хранилище: демо генерируется в браузере детерминированно (seed); импорт сохраняется в
`localStorage` компактным JSON. Настройки — тоже `localStorage`.

## 2. Периоды (`src/core/periods.ts`)

Все даты — строки ISO, арифметика в днях от эпохи (UTC) — без сдвигов часовых поясов.
Неделя — ISO: понедельник–воскресенье. Номер недели и «год недели» — по ISO 8601 (неделя
принадлежит году, в который попадает её четверг: 29.12.2025 — это 2026-W01).

Опорная дата `ref` — последняя дата в данных (или выбранная вручную в настройках).

| Период | Интервал | Предыдущий такой же |
|---|---|---|
| Прошлая неделя | пн–вс недели перед неделей `ref` | неделя перед ней (позапрошлая) |
| Неделя (накоп.) | пн недели `ref` … `ref` | прошлая неделя пн … тот же день недели |
| Месяц (накоп.) | 1-е число … `ref` | 1-е прошлого месяца … тот же день (обрезается по длине месяца) |
| С начала года | 1 января … `ref` | 1 января прошлого года … та же дата (29.02 → 28.02) |
| Произвольный | от … до (календарь) | такой же длины сразу перед ним |

Недели плана в периоде: недели, чей четверг попадает в период; завершённой считается неделя,
воскресенье которой ≤ `ref`. Так неделя на стыке месяцев/лет учитывается ровно один раз.

## 3. Формулы метрик

- **Звонки / Встречи** — количество строк с `type`.
- **Результаты** — разбивка по `result` отдельно для звонков и встреч.
- **Конверсия звонок → встреча** = звонки с результатом «договорились о встрече» / все звонки.
- **Активность** (метрика рейтинга по умолчанию) = звонки + встречи.
- **Стратегическая встреча**: `type = meeting` и
  - режим `auto` (по умолчанию): если есть `daysSinceLastMeeting` — `≥ порога (180)` или
    `newClient`; иначе — флаг `kind = strategic` из источника;
  - режим `days`: только по дням/признаку нового клиента; режим `flag`: только по флагу.
- **Фоллоуап**: `kind = followup` (звонок или встреча). Стратегическая встреча фоллоуапом
  не считается (настройка `strategicCountsAsFollowup = false`).
- **План недели**: `S = min(стратег, 3)/3`, `F = min(фоллоуап, 6)/6`, выполнение `= (S + F)/2`.
  Статус: «выполнен» — оба норматива достигнуты; «не начат» — 0 и 0; иначе «частично».
- **За месяц / с начала года**: число завершённых недель периода со статусом «выполнен».
- **Рейтинг**: место по выбранной метрике (ничья — одинаковое место), отклонение от среднего по
  команде (абс. и %), отставание от лучшего, динамика к предыдущему такому же периоду (%).
- **Внимание**: падение активности ≥ 30% к предыдущему периоду (при базе ≥ 5), активность ниже
  порога, 0 встреч за последние 7 дней, план прошлой недели не начат.
- **Прогноз месяца** = факт / прошедшие рабочие дни × рабочих дней в месяце.
- **План/факт**: норматив звонков и встреч на менеджера в неделю (настройки); на месяц — недельный ×
  рабочие дни / 5.

## 4. Экраны (макеты)

```
┌ Шапка: название · [Прошлая неделя|Неделя|Месяц|С начала года|Период] · Подразделение · Менеджер · Продукт · тема · печать
├ Навигация: Обзор | Рейтинг | План 3+6 | Сравнение | Внимание | Импорт | Настройки
```

1. **Обзор**: 4 KPI-плитки (звонки, встречи, конверсия, активные менеджеры) с ▲▼ к предыдущему
   периоду · статус плана команды (выполнили/частично/не начали) · линия динамики по неделям
   (звонки и встречи — два отдельных графика, одна ось у каждого) · сводка недели текстом ·
   план/факт с прогнозом · воронка.
2. **Рейтинг**: таблица (сортировка по клику на любой заголовок): место, менеджер, звонки,
   встречи, конверсия, стратег., фоллоуапы, план %, Δ к пред., от среднего, от лучшего,
   sparkline 12 недель. Экспорт CSV/XLSX.
3. **План 3+6**: менеджер × последние недели, в клетке «N/3 · N/6» + цвет + значок; сводка
   команды по выбранной неделе; недель выполнено за месяц и с начала года.
4. **Сравнение**: тепловая карта «менеджер × неделя» (звонки/встречи), «менеджер × продукт»,
   воронка по менеджерам, глубина портфеля, редкие продукты, выбор 2–4 менеджеров бок о бок.
5. **Карточка менеджера**: KPI с местом в команде, звонки и встречи по неделям (vs среднее
   команды), конверсия по неделям, история плана, продукты.
6. **Внимание**: список сигналов с причиной и ссылкой на карточку.
7. **Импорт**: файл CSV/XLSX → автосопоставление колонок → ручная правка → предпросмотр → загрузка.
8. **Настройки**: пороги и нормативы, режим стратегических встреч, опорная дата.

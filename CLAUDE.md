# CLAUDE.md — дашборд активности клиентских менеджеров (РМ)

## Стек
- Vite 8 + TypeScript 5.9 (strict, `erasableSyntaxOnly`), без UI-фреймворка: экраны — функции, возвращающие DOM.
- Графики — ручной SVG (`src/ui/charts.ts`), без библиотек.
- Тесты — Vitest. Линт — ESLint 9 + typescript-eslint (flat config).
- XLSX: `read-excel-file` (импорт), `write-excel-file` (экспорт). CSV — свой парсер.
- Данные: демо генерируется детерминированно в браузере; импорт хранится в `localStorage` браузера. Внешних серверов нет.

## Структура
```
src/core/      чистая логика без DOM: даты и периоды, классификация, метрики, рейтинг, внимание, сводка
src/data/      демо-генератор, CSV, импорт и сопоставление колонок, хранилище, экспорт
src/ui/        DOM-хелперы, SVG-графики, форматирование, каркас (навигация, фильтры)
src/ui/screens/ экраны: overview, ranking, compare, manager, plan, attention, import, settings
scripts/       generate-demo.ts — выгрузка демо в CSV (data/sample/)
tests/         Vitest-тесты (*.test.ts)
docs/PLAN.md   модель данных, формулы, макеты
data/private/  реальные выгрузки — в .gitignore
```
Импорты между модулями — с расширением `.ts` (нужно для запуска скриптов через Node без сборки).

## Команды
- `npm run dev` — dev-сервер Vite (http://localhost:5173)
- `npm test` — Vitest (однократно)
- `npm run build` — `tsc --noEmit` + `vite build`
- `npm run lint` — ESLint
- `npm run demo` — записать демо-данные в `data/sample/demo.csv`

Перед коммитом: `npm test && npm run build && npm run lint`.

## Правила
- НЕ коммитить секреты (`.env`, ключи API, токены) и реальные данные клиентов.
- В приложении и репозитории — только агрегаты по менеджерам. Имена клиентов, телефоны, счета, ИНН не хранить и не показывать: импорт берёт только сопоставленные колонки, остальное отбрасывает.
- Реальные выгрузки — только в `data/private/` (игнорируется git).
- Демо-имена менеджеров вымышленные.
- Логика расчётов — в `src/core` с тестами; UI не считает метрики сам.
- Цвет не единственный носитель смысла: всегда стрелка ▲▼ и/или подпись.
- Новые решения записывать в README → «Решения». Держать этот файл актуальным.
- Коммитить по шагам, сообщения на русском.
